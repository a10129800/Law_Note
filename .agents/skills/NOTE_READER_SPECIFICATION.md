## 一、核心工作準則與教材依據原則

### 1.1 嚴格書本依據（Strict Textbook Fidelity）
- **禁止自行查找或腦補學說**：嚴禁在未收到使用者提供的教材實質內容前，依據 AI 外部記憶或個人推測自行填寫學說爭點。
- **逐頁逐節精準對照**：所有單元、章節、圖解與案例，皆必須精準標註教材頁碼（例如：`教材第 2-25 ～ 2-27 頁`）。
- **保留插槽機制**：若使用者尚未提供某一小節之詳細教材，在中欄保留標準質感的「待填入插槽卡片」，絕不任意填塞假資料。

### 1.2 現行法規與實務即時查核
- 當教材涉及舊法規或關鍵釋字（如保安處分修法、累犯釋字 775 號、性自主修法等）時，必須在卡片備註標明「現行法修正狀態」與「憲法法庭裁判拘束」，確保法律內容既忠於教材，又符合現行法制。

## 二、圖表格式與全景流程圖規範 (Draw.io Flowchart Standard)

### 2.1 圖 1 標準風格復刻
- **體系全景化**：凡涉及跨節或章前引導時，必須採用 **Draw.io 格式標準** 製作全景流程圖（包含分支、匯流、巢狀方框、多色向度劃分）。
- **完整統整性**：全景圖必須一圖涵蓋章節的所有核心維度（例如：應報、一般預防、特別預防、結合理論、雙軌制裁門檻與四大審查步驟）。

### 2.2 靜態檔案輸出與「禁止拖拽」鐵律
- **固定圖片檔案**：流程圖必須以獨立的靜態向量圖（`.svg`）或高解析度圖片（`.webp` / `.png`）載入，放置於 `images/` 目錄中。
- **嚴格禁止拖曳移動**：
  在 HTML 標籤與 CSS 樣式中，必須嚴格配置防拖曳與防反白設定，避免使用者滾動或選取時產生惱人的拖曳殘影：
  ```html
  <img 
    id="flowchartImg"
    src="images/part0-ch3-flowchart.svg" 
    alt="體系流程圖" 
    draggable="false"
    class="w-full h-auto block select-none pointer-events-auto cursor-zoom-in rounded-2xl"
    style="-webkit-user-drag: none; user-select: none; -webkit-touch-callout: none;"
  />
  ```

### 2.3 字體可讀性與高對比鐵律 (Ultra-Sharp & High-Contrast)
> 🚨 **痛點防範**：絕對禁止出現字體太小、字重太細、灰底配淺灰字等看不清楚的低劣圖表！

- **字級標準規範**：
  | 項目 | 最低字級要求 | 字重 (Font Weight) | 顏色標準 |
  | :--- | :--- | :--- | :--- |
  | **主圖大標題** | `22px ～ 26px` | Black (900) | 深黑或主題主色（如深藍 `#1E3A8A`） |
  | **主要分類群組標籤** | `17px ～ 20px` | Extra Bold (800) | 高飽和主題深色 |
  | **節點標題與核心結論** | `15px ～ 17px` | Bold (700) | 深色、帶強烈識別度 |
  | **卡片內部說明內文** | `14px ～ 15.5px` | Semi-Bold / Medium | 深深色（如 `#1E293B`），嚴禁淡灰 |
- **線條與邊框**：
  - 流程引導線寬度不得小於 `2.5px ～ 3px`，箭頭必須清晰鮮明。
  - 方框底色採用柔和但具層次感之淺色漸層（如冰藍、薄荷綠、淡琥珀），文字與底色對比度（Contrast Ratio）必須大於 `4.5:1`。

### 2.4 雙重視角控制與全螢幕放大燈箱
流程圖展示容器頂部必須統一配置控制工具列：
1. **「適配頁面」按鈕**：寬度限制為 100%，自動適應三欄式版面。
2. **「100% 原始大圖」按鈕**：展開為原始真實解析度（支援容器橫向滾動），供超寬流程圖細部研讀。
3. **「全螢幕檢視」按鈕**：點擊圖片任何一處或按鈕，立刻啟動高解析燈箱（Canvas `maxWidth: 1140px+`），支援滑鼠滾輪縮放與自由平移。

## 三、流程圖專屬白話文專區規範 (Plain-Language Flowchart Guide Standard)

> 💡 **使用者核心需求**：「流程圖下方也要有白話文專區，講解這個流程圖的內容。」

流程圖具備強烈邏輯性，但若缺乏通俗導讀，初學者容易望圖生畏。因此，在全景流程圖容器下方，必須緊鄰配置一個**專屬的「白話文速讀專區」**：

1. **直接映射流程圖各區塊**：
   - 導讀內容必須採用清晰的序號（①、②、③、④），一一對應流程圖的上下左右核心區塊。
   - 例如刑罰目的流程圖：
     - **區塊 ①：算舊帳 vs. 防未來**（應報與預防，融合以牙還牙、孫武練兵與杜鵑窩典故）
     - **區塊 ②：現代通說結合理論**（罪責上限黃金公式）
     - **區塊 ③：雙軌制裁體系**（處罰與看病：TB+R+S vs. TB+R）
     - **區塊 ④：落地執行四大步驟**（法定刑 ➔ 處斷刑 ➔ 宣告刑 ➔ 執行刑）
2. **生動白話與重點提煉**：
   - 用大眾秒懂的文字精煉法理，點出法律背後的生活哲理（如「做多少壞事受多少處罰」、「處罰與看病雙管齊下」）。
   - 底部附帶「圖解銜接提示」，引導讀者自然進入下一大段。
3. **右側目錄（TOC）獨立導航**：
   - 該白話文專區必須擁有專屬 ID（如 `sec-p0ch3-flowchart-guide`），並在右側 TOC 中列出子項（如 `　└ 💡 流程圖白話文速讀專區`），方便讀者一鍵跳轉。

## 四、內容防重複與去冗餘化鐵律 (Zero-Redundancy Standard)

> 💡 **核心原則**：「拒絕零碎散落的重複卡片，建立集中式白話專區！」

- **集中導讀，杜絕散彈打鳥**：
  所有針對流程圖的白話解釋、典故解說與理論比對，必須**統一收納於流程圖下方的白話文專區內**。
- **嚴禁在圖外到處重複散落贅述卡片**：
  - ❌ 禁止：在白話專區外，又開一節放 3 張大典故卡片、又開一節放 4 張大賣場購物卡片。
  - ❌ 禁止：將同一個理論在不同的卡片中重複敘述 3 到 4 遍。
  - ✅ 正確佈局：**前導引言 ➔ 體系全景圖 ➔ 流程圖白話專區 ➔ 原書特有圖說（圖4）➔ 下一節**。

## 五、三欄漸進式閱讀器架構 (3-Column Layout & Progressive Disclosure)

```text
+---------------------------------------------------------------------------------------+
|  左側導航樹 (Sidebar)   |         中欄主閱讀區 (Main Reader)        | 右側目錄 (TOC Scrollspy) |
|                         |                                           |                         |
|  🏠 書籍主頁 (Home)     |  [麵包屑導航]  [教材頁碼徽章]              |  📌 第三章 法律效果 清單 |
|  📖 本篇導讀 (Intro)    |  ---------------------------------------  |  ---------------------  |
|  📂 篇章巢狀選單        |  一、犯罪成立後的最終考驗 (引言)           |  一、犯罪成立後的最終考驗 |
|    ├ 第一章 犯罪的概念  |  二、刑罰目的理論體系全景流程圖 (Draw.io)  |  二、刑罰目的理論體系全景 |
|    ├ 第二章 論罪結構    |      [適配 / 100% 原圖] [全螢幕放大]       |  　├ 📊 體系全景圖       |
|    └ 第三章 法律效果    |      [高對比・大字體・禁止拖曳 SVG]        |  　└ 💡 白話文速讀專區   |
|      ├ 第一節 法定刑    |      💡【白話文專區】核心脈絡速讀導引      |  三、刑罰思考四大步驟     |
|      ├ 第二節 處斷刑    |  三、原書架構圖解：思考四大步驟 (圖4復刻)  |  👉 第一節 刑罰種類 →    |
|      ├ 第三節 宣告刑    |  ---------------------------------------  |  👉 第二節 刑罰調整 →    |
|      └ 第四節 執行刑    |  [← 上一單元]                 [下一單元 →]  |  🏠 回到書籍主頁         |
|                         |                                           |  [🔝 回到頁首]           |
+---------------------------------------------------------------------------------------+
```

### 5.1 漸進式閱讀三態控制（Progressive Disclosure）
1. **狀態 0（書籍主頁 `home`）**：
   - 僅展示書籍中繼資料、3D 立體書封、教材特色卡與快速開始按鈕。
   - **右側清單完全隱藏**。
2. **狀態 1（本篇導論 `intro` / `part-0`）**：
   - 僅展示該篇宏觀導讀與框架引言，不展示細節章節，營造專注氛圍。
   - **右側清單完全隱藏**。
3. **狀態 2（章節／小節閱讀 `part0-chapter-3` 等）**：
   - 中欄展示該章節完整圖說與精煉內文。
   - **右側清單同步顯現並吸頂跟隨**，支援 Scrollspy 即時滾動高亮。

### 5.2 左側樹狀選單規範
- **父層大綱**：字級 `14px ～ 14.5px`，`font-bold`，配大綱圖示。
- **子章節／小節**：
  - 字級一律縮小為 **`text-[13px]`**，維持精緻細膩。
  - 左側外圍帶有引導線：`ml-4 pl-3 border-l-2 border-slate-200 dark:border-slate-800/80`。
  - 每個按鈕前端配備微型指示圓點：`w-1.5 h-1.5 rounded-full`。

### 5.3 右側動態章節目錄 (Right TOC Scrollspy)
- 清單項目與中欄的各個 `<section id="...">` 與重點導讀卡錨點嚴格一對一對應。
- 支援「平滑滾動（Smooth Scroll）」、「當前閱讀段落高亮（Active State）」與「點擊直達」。
- 底部常駐「🏠 回到書籍主頁」與「🔝 回到頁首」快捷鍵。

## 六、DOM 結構閉合與標籤平衡鐵律 (HTML Tag Integrity)

### 6.1 嚴防「多餘閉合標籤（Stray Closing Tag Trap）」
- **致命災難**：在小節卡片內部如果多寫了一個 `</div>`，會導致中央 `<main>` 與最外層網格 `.app-layout-container` 提前閉合。
- **破版現象**：右側清單 `#rightTocAside` 被強制踢出三欄網格外，掉落至全螢幕最下方或左下角橫向展開，右側完全空白。
- **鐵律檢驗**：最外層 `.app-layout-container` 內部**有且僅有 3 個一級子節點**：
  1. `aside#sidebar`（左側選單）
  2. `main`（中央閱讀區）
  3. `aside#rightTocAside`（右側目錄）

### 6.2 Section 標籤成對平衡自檢
每個小節的結構必須嚴格成對閉合，不得交錯：
```html
<!-- 正確範例 -->
<section id="sec-xxx" class="space-y-6 pt-2">
  <div class="flex items-center justify-between border-b ...">
    <!-- Header -->
  </div>
  <div class="p-6 rounded-3xl ...">
    <!-- 內容卡片 -->
  </div>
</section> <!-- 嚴格成對閉合 -->
```

## 七、全站聯動同步清單 (TOC & Search DB Synchronization)

當您新增、修改章節結構，或調整白話文導引區塊時，**必須同時同步以下三處檔案**：

| 步驟 | 目標檔案 | 同步項目說明 |
| :---: | :--- | :--- |
| **1** | `content/view-{chapter}.js` | 調整內文段落 `<section id="...">` 與卡片 ID，確保標籤完全平衡。 |
| **2** | `data/toc-config.js` | 更新對應章節 key 下的 `items` 清單，確認 `id` 錨點完全存在，無失效連結。 |
| **3** | `data/search-db.js` | 更新搜尋資料庫中的項目標題、關鍵字與 `anchor` 導航錨點，確保 Cmd+K 搜尋精準直達。 |

## 🎯 總結：開發檢驗清單 (Checklist)
每次修改或交付全新筆記頁面時，請自我核對以下 7 點：
- [ ] 1. **全景圖是否為靜態高畫質圖檔**，且已配置 `draggable="false"`、`user-select: none`？
- [ ] 2. **圖表字體是否夠大（>14.5px）、對比是否清晰鮮明**，絕無模糊小字？
- [ ] 3. **流程圖下方是否具備專屬「白話文速讀專區」**，條理分明拆解圖內核心？
- [ ] 4. **圖外是否已徹底清除零散重複的卡片**，沒有反覆重講圖內已有的定義與典故？
- [ ] 5. **流程圖與白話導引後是否順暢銜接原書圖解或進階研讀章節**？
- [ ] 6. **右側 TOC 清單是否正常吸頂顯現**，無破版或掉落至頁底？
- [ ] 7. `view-*.js`、`toc-config.js` 與 `search-db.js` **三者錨點是否完全吻合**？
